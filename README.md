# williamschober.github.io

Personal website and CV of William Schober, served by GitHub Pages at
<https://williamschober.github.io>.

The site is a single static page with no build step. The same HTML page is the
CV: [`cv.pdf`](cv.pdf) is generated by printing `index.html` to PDF with
headless Chrome. The print styles leave out website-only content such as the
introductory bio.

## Files

| File | Purpose |
| --- | --- |
| `index.html` | The whole site: header, bio, and sections for education, publications, teaching, talks and posters |
| `style.css` | Styles for screen, dark mode, mobile (`max-width: 600px`) and print (`@media print`, used for the PDF) |
| `photo.jpg` | Portrait shown in the header |
| `photo_bw.jpg` | Black-and-white portrait (not currently used by the page) |
| `cv.pdf` | Generated CV, linked from the header. Do not edit by hand |
| `scripts/generate_cv_pdf.py` | Regenerates `cv.pdf` from `index.html`, `style.css` and `photo.jpg` |

## Editing the site

1. Edit `index.html` and/or `style.css`.
2. Preview by opening `index.html` in a browser. Use the browser's print preview
   to check how the CV PDF will look.
3. Regenerate `cv.pdf` (see below).
4. Commit and push to `main`. GitHub Pages publishes the change within a minute
   or two.

New entries in a section follow this pattern:

```html
<div class="entry">
  <div class="when">2026</div>
  <p class="what"><strong>Title</strong>, details
    <br><span class="detail">Extra line in smaller text</span></p>
</div>
```

### Website-only content

Anything with the class `screen-only` appears on the website but not in the CV
PDF (it is hidden by `@media print` in `style.css`). The introductory bio and
the "CV" link in the header use it. For inline content, wrap the trailing space
too, so no stray gap is left in the PDF:

```html
<span class="screen-only"><a href="cv.pdf">CV</a> </span>
```

### Font sizes and the PDF

The print styles set the root size (`html { font-size: 10pt; }`) rather than
the body size, so everything sized in `rem` (headings, columns, the photo,
spacing) shrinks by the same factor and the PDF keeps the website's
proportions. Text that should be smaller or larger than the surrounding text
(dates, details, contact list, footer) is sized in `em`, so it follows the body
size. Keep to these units when adding styles, and check the page count of
`cv.pdf` after changes.

## Generating the CV PDF

Requirements: macOS, Python 3, and Google Chrome installed at
`/Applications/Google Chrome.app`. The script uses only the Python standard
library.

```sh
# Generate cv.pdf once
python3 scripts/generate_cv_pdf.py

# Regenerate cv.pdf whenever index.html, style.css or photo.jpg changes
python3 scripts/generate_cv_pdf.py --watch
```

The script waits for the source files to stop changing, renders the PDF in a
temporary Chrome profile without headers or footers, checks that the output is
a valid PDF, and replaces `cv.pdf` atomically. If the sources change mid-render
it tries again.

### Automatic regeneration in VS Code

When the parent `Website` folder is opened in VS Code, the task
**Watch and generate CV PDF** in `../.vscode/tasks.json` starts the watcher
automatically (`runOn: folderOpen`). VS Code may ask once to allow automatic
tasks for the folder. The task points at the Python 3.13 framework install;
update the `command` path there if Python lives elsewhere.

Remember to commit the regenerated `cv.pdf` together with the HTML changes.
